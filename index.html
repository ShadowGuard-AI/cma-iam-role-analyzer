One Named Role

cma-iam-role-analyzer analyzes IAM roles in AWS to identify potential privilege escalation paths. It uses boto3 with the operator's own AWS profile. It is AWS only, and it works on a single named role.

If a role lookup fails, the run reports the error and exits 1 instead of returning an empty result.

Three Checks at the Door

Wildcard actions.

Wildcard resources.

sts:AssumeRole.

Managed Policies and Inline Policies

The attached managed policies of the role.

The inline policies of the role.

A flagged statement receives at most one of the three checks, because the tests run as a chain.

Usage, Two Lines Side by Side

./cma-iam-role-analyzer [params]

That line is a placeholder. The invocation the argument parser in main.py actually accepts is:

python3 main.py --role-name ROLE [--profile PROFILE] [--region REGION] [--output-file FILE]

Here --role-name is required, and the remaining options follow it. The README line is not rewritten to look correct; the two lines stand side by side so a reader can see the gap.

What a Clean Run Does Not Prove

Only statements whose effect is Allow are examined, and conditions on a statement are never read, so a grant narrowed by a condition flags in the same way as an open one.

The three tests are exact matches. A service shaped grant, one ending in a colon and a star, is not caught by the wildcard action test. A resource string ending in a slash and a star is not caught by the wildcard resource test.

Because the tests run as a chain, one statement receives at most one reason, even when more than one of the three applies to it.

A run that finds nothing therefore means that none of the three checks matched. It does not mean that no privilege escalation path exists.
